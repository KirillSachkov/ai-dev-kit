# Скиллы

Скилл даёт агенту инструкции для конкретной задачи. Здесь отдельно описаны сторонние полезные скиллы и два проводника по этому набору.

[Главная](../README.md) · [Инструменты](../TOOLS.md) · [Источники](../sources/README.md)

## Полезные скиллы

[mattpocock/skills](https://github.com/mattpocock/skills) содержит скиллы Matt Pocock для инженерной работы с агентом. Его pipeline связывает обсуждение требований, спецификацию, задачи, реализацию и ревью. Отдельные скиллы можно выбирать под свой проект. Кирилл Сачков использует этот подход; автор скиллов и оригинального pipeline является Matt Pocock.

Если нужны оригинальные скиллы Matt Pocock, выбери нужные папки из [upstream](https://github.com/mattpocock/skills) на проверенном commit и перенеси их целиком со ссылочными файлами, доступными metadata и лицензией. Используй поддерживаемый механизм установки своего агента в папке проекта. Если выбираешь CLI-установщик, сначала проверь его версию и источник, затем закрепи проверенную версию. Поведение upstream setup зависит от выбранной версии; описанная ниже схема `AGENTS.md`/`WORKFLOW.md` относится к адаптированному набору Кирилла Сачкова.

Для настройки project-owned harness с этой схемой используй [адаптированный shared set на commit `d459183`](https://github.com/KirillSachkov/workspace/tree/d459183/pipeline/skills). Его минимальная копия уже находится в `.agents/skills/` этого репозитория: `implement-spec`, `tdd`, `code-review`, `classify-change` и `setup-matt-pocock-skills`. [Происхождение, лицензия и manifest](../docs/pipeline-source/README.md) фиксируют полный commit, состав и hashes. Для переноса выбери нужные папки из этого закреплённого набора, сохрани их целиком с metadata/references и лицензией. Это shared-адаптация исходных скиллов Matt Pocock, а не неизменённый upstream или обещание автоматической синхронизации.

В адаптированном наборе включи `setup-matt-pocock-skills` только если нужна настройка процесса, и запусти его явно в своём проекте. Проект выбирает tracker, нужные stages, проверки, review и полномочия. Канонические инструкции проекта хранятся в `AGENTS.md`; поддерживаемый Claude Code читает их нативно. Состояние сессии и classification принадлежат корневому `WORKFLOW.md`, а `.claude/skills` сохраняет discovery скиллов. Установка не переносит глобальные разрешения и не запускает следующие stages автоматически. Пользовательские проводники ниже остаются самостоятельными материалами набора.

## Скиллы этого набора

| Скилл | Когда нужен |
|---|---|
| [sachkov-ai-kit](sachkov-ai-kit/SKILL.md) | Разобраться в наборе Кирилла, найти материал и выбрать компоненты |
| [setup-ai-stack](setup-ai-stack/SKILL.md) | Настроить выбранную тему или инструмент и проверить результат |

Начни с главного скилла, если ещё выбираешь. Если выбор уже сделан, используй помощник настройки. Он сохраняет твой редактор и помогает по одному компоненту.

## Запуск из репозитория

Открой папку набора в Codex или Claude Code. Относительные ссылки в `.agents/skills/` и `.claude/skills/` ведут к двум папкам в `skills/`. Канонические инструкции хранятся в одном месте.

Можно указать путь `skills/sachkov-ai-kit/SKILL.md` в запросе. Такой запуск не требует отдельной установки.

## Установка скиллов набора

Чтобы использовать скилл в другом проекте, попроси агента установить выбранную папку из `skills/` через его поддерживаемый механизм. Переноси всю папку, включая `references/` и `agents/`. При копировании через ссылку бери содержимое её целевой папки.

Отдельный скилл сохраняет контекст автора и ссылки на публичные материалы. Конфиги остаются в репозитории. Для настройки укажи путь к клону или попроси агента получить набор.

Пример для установленного скилла:

```text
Используй $setup-ai-stack. Клон набора находится в ~/Projects/ai-dev-kit.
Хочу только тему Ghostty на macOS. Мой редактор оставь VS Code.
```
